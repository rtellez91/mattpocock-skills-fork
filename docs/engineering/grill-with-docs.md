## What it does

Sharpen an idea through the existing interview while recording domain terms and decisions. Product-experience questions additionally use UX discovery, without replacing the interview.

## When to reach for it

You invoke this with `/grill-with-docs`; the agent does not start it automatically. Reach for it for a coherent question you can explore in a conversation. Use Wayfinder for several related explorations that need a persistent map.

## Prerequisites

Use a project workspace: this interview maintains `GLOSSARY.md` and architectural decision records there. Keep the original `grilling` and `domain-modeling` skills installed.

## Common questions

**Does every interview need a journey map or prototype?**

No. The agent selects a method only when it helps resolve a concrete uncertainty. It distinguishes completed requirements discussion from explicitly deferred design.

## It's working if

The questions remain yours to answer, UX methods have a reason, and findings return to the same conversation.

## Where it fits

This is the interview step before [to-spec](https://github.com/rtellez91/mattpocock-skills-fork/blob/product-ux/docs/engineering/to-spec.md), which synthesizes the resulting decisions. [Wayfinder](https://github.com/rtellez91/mattpocock-skills-fork/blob/product-ux/docs/engineering/wayfinder.md) handles a larger web of uncertainty. [Ask Matt](https://github.com/rtellez91/mattpocock-skills-fork/blob/product-ux/docs/engineering/ask-matt.md) maps the full workflow.
